## 一、功能总览

| 功能模块 | 说明 |
|---------|------|
| 第三方登录 | 用户用微信/抖音/支付宝扫码或授权后，直接登录本站 |
| 自动注册 | 首次第三方登录时，自动创建本站账号 |
| 账号绑定 | 已登录用户可绑定第三方账号，绑定后可用第三方直接登录 |
| 账号解绑 | 用户可解除已绑定的第三方账号 |
| 绑定查询 | 查询当前用户已绑定的第三方账号列表 |
| 多平台绑定 | 一个本站账号可同时绑定微信、抖音、支付宝 |
| 唯一性约束 | 同一第三方账号只能绑定一个本站用户 |
| **Mock 模式（v2 新增）** | 无需企业认证即可模拟完整 OAuth 流程，支持前后端全链路联调 |
| **平台沙盒对接（v2 新增）** | 对接支付宝沙箱环境，使用测试凭证调试真实接口 |

## 三、详细需求

### 3.1 微信扫码登录

| 需求项 | 内容 |
|-------|------|
| **接入平台** | 微信开放平台 — 网站应用 |
| **前置条件** | 企业认证 + 创建网站应用 + 配置授权回调域 |
| **凭证** | AppID（`wx` 开头）、AppSecret（32位十六进制） |
| **授权 Scope** | `snsapi_login` |
| **授权页地址** | `https://open.weixin.qq.com/connect/qrconnect?appid={APPID}&redirect_uri={REDIRECT_URI}&response_type=code&scope=snsapi_login&state={STATE}#wechat_redirect` |
| **Token 换取** | GET `https://api.weixin.qq.com/sns/oauth2/access_token?appid={APPID}&secret={SECRET}&code={CODE}&grant_type=authorization_code` |
| **用户信息** | GET `https://api.weixin.qq.com/sns/userinfo?access_token={TOKEN}&openid={OPENID}` |
| **唯一标识** | `openid` |
| **可获取字段** | openid、nickname、headimgurl、sex、country、province、city |
| **回调地址要求** | 仅域名，不含 `http://`，需通过域名验证 |
| **注意事项** | 2021年后注册的公众号无法获取用户昵称头像，需用户手动填写 |

#### 接口流程

```
用户点击"微信登录"
    ↓
后端 GET /auth/oauth/wechat/authorize → 返回微信授权页 URL
    ↓
前端跳转到微信扫码页
    ↓
用户扫码确认 → 微信回调前端 ?code=xxx&state=xxx
    ↓
前端 POST /auth/oauth/wechat/callback { code, state }
    ↓
后端：换 access_token → 获取 openid + 用户信息 → 查找/创建用户 → 签发 JWT
```

### 3.2 抖音扫码登录

| 需求项 | 内容 |
|-------|------|
| **接入平台** | 抖音开放平台 — 网站应用 |
| **前置条件** | 企业认证 + 创建网站应用 + 配置重定向 URL |
| **凭证** | ClientKey、ClientSecret |
| **授权 Scope** | `user_info`（PC端扫码）/ `login_id`（端内静默授权） |
| **授权页地址** | `https://open.douyin.com/platform/oauth/connect/?client_key={KEY}&response_type=code&scope=user_info&redirect_uri={REDIRECT_URI}&state={STATE}` |
| **Token 换取** | POST `https://open.douyin.com/oauth/access_token/` Body: `{"client_key": "{KEY}", "client_secret": "{SECRET}", "code": "{CODE}", "grant_type": "authorization_code"}` |
| **用户信息** | GET `https://open.douyin.com/oauth/userinfo/?access_token={TOKEN}&open_id={OPENID}` |
| **唯一标识** | `open_id` |
| **可获取字段** | open_id、nickname、avatar、gender、country、province、city |
| **回调地址要求** | 完整 URL，需与开放平台配置完全一致 |
| **Code 有效期** | 10 分钟，仅可用一次 |
| **特殊限制** | `login_id` scope 需白名单开通；redirect_uri 不支持携带自定义 query 参数 |

#### 接口流程

```
用户点击"抖音登录"
    ↓
后端 GET /auth/oauth/douyin/authorize → 返回抖音授权页 URL
    ↓
前端跳转到抖音扫码页
    ↓
用户扫码确认 → 抖音回调前端 ?code=xxx&state=xxx
    ↓
前端 POST /auth/oauth/douyin/callback { code, state }
    ↓
后端：换 access_token → 获取 open_id + 用户信息 → 查找/创建用户 → 签发 JWT
```

### 3.3 支付宝授权登录

| 需求项 | 内容 |
|-------|------|
| **接入平台** | 支付宝开放平台 — 网页应用 |
| **前置条件** | 企业认证 + 创建应用 + 应用上线 + 配置授权回调地址 |
| **凭证** | AppID、应用私钥（RSA2）、支付宝公钥 |
| **授权 Scope** | `auth_user`（获取用户信息） |
| **授权页地址** | `https://openauth.alipay.com/oauth2/publicAppAuthorize.htm?app_id={APPID}&scope=auth_user&redirect_uri={REDIRECT_URI}&state={STATE}` |
| **Token 换取** | 调用 `alipay.system.oauth.token` 接口（需 RSA2 签名） |
| **用户信息** | 调用 `alipay.user.info.share` 接口（需 access_token） |
| **唯一标识** | `user_id`（2088 开头的 16 位数字） |
| **可获取字段** | user_id、nick_name、avatar、gender、province、city |
| **回调地址要求** | 完整 URL，需与配置中心一致 |
| **auth_code 有效期** | 最短 3 分钟，最长 24 小时，仅可用一次 |
| **特殊限制** | 所有请求需 RSA2 签名验签；需安装支付宝 SDK 或自行实现签名 |

#### 接口流程

```
用户点击"支付宝登录"
    ↓
后端 GET /auth/oauth/alipay/authorize → 返回支付宝授权页 URL
    ↓
前端跳转到支付宝授权页
    ↓
用户确认授权 → 支付宝回调前端 ?auth_code=xxx&state=xxx
    ↓
前端 POST /auth/oauth/alipay/callback { code: auth_code, state }
    ↓
后端：RSA2签名调用 alipay.system.oauth.token → 获取 access_token + user_id
      → 调用 alipay.user.info.share 获取用户信息
      → 查找/创建用户 → 签发 JWT
```

## 四、Mock 模式 + 平台沙盒方案（v2 新增）

> 开发阶段无需企业认证，通过 Mock 模式 + 平台沙盒即可完成前后端全链路开发与联调。

### 4.1 方案总览

| 方案 | 适用平台 | 原理 | 优点 | 缺点 |
|------|---------|------|------|------|
| **Mock 模式** | 微信、抖音、支付宝 | 后端模拟 OAuth 全流程，不调用真实第三方接口 | 完全自主可控，不限平台，零成本 | 测试数据为模拟数据 |
| **支付宝沙盒** | 支付宝 | 对接支付宝官方沙箱环境，使用测试凭证调用真实接口 | 接口真实，可验证签名/网关逻辑 | 仅支付宝支持，需生成 RSA2 测试密钥 |
| **微信测试号** | 微信（公众号网页授权） | 微信公众平台接口测试帐号 | 接口真实 | 仅支持公众号网页授权，不支持开放平台扫码登录 |

### 4.2 Mock 模式设计

#### 4.2.1 核心机制

```
开启 Mock 模式（OAUTH_MOCK_MODE=true）

GET /auth/oauth/{provider}/authorize
    ↓
返回本地 Mock 授权页 URL：/mock/oauth/{provider}?state=xxx
    ↓
前端跳转到 Mock 授权页
    ↓
Mock 授权页展示"模拟扫码"界面 + 测试账号选择 + "确认授权"按钮
    ↓
用户点击确认 → 前端回调 ?code=mock_code_xxx&state=xxx
    ↓
前端 POST /auth/oauth/{provider}/callback { code, state }
    ↓
后端 Mock 分支：
    1. 校验 state
    2. 根据 code 匹配预设测试账号
    3. 返回该测试账号的用户信息（openid/nickname/avatar）
    4. 查找/创建用户 → 签发真实 JWT
    ↓
前端收到 JWT，登录完成
```

#### 4.2.2 Mock 授权页需求

| 需求项 | 说明 |
|-------|------|
| 页面路径 | `/mock/oauth/{provider}` |
| 页面内容 | 模拟第三方授权界面风格（微信绿/抖音黑/支付宝蓝） |
| 核心元素 | 平台 Logo + "模拟授权登录" 标题 + 测试账号下拉框 + "确认授权" 按钮 |
| 测试账号 | 每个平台预设 2 个测试账号，可选其一授权 |
| 行为 | 点击"确认授权"后，生成 `mock_code_{provider}_{account_index}_{timestamp}`，回调到前端回调页 |
| 安全提示 | 页面顶部显示"⚠️ Mock 模式 — 仅供开发调试，请勿用于生产环境" |

#### 4.2.3 测试账号体系

| 平台 | 账号序号 | openid / open_id / user_id | 昵称 | 头像 |
|------|---------|---------------------------|------|------|
| 微信 | 1 | `mock_wechat_openid_001` | 测试微信用户A | https://mock-cdn.test/avatar/wechat_001.png |
| 微信 | 2 | `mock_wechat_openid_002` | 测试微信用户B | https://mock-cdn.test/avatar/wechat_002.png |
| 抖音 | 1 | `mock_douyin_openid_001` | 测试抖音用户A | https://mock-cdn.test/avatar/douyin_001.png |
| 抖音 | 2 | `mock_douyin_openid_002` | 测试抖音用户B | https://mock-cdn.test/avatar/douyin_002.png |
| 支付宝 | 1 | `2088000000000001` | 测试支付宝用户A | https://mock-cdn.test/avatar/alipay_001.png |
| 支付宝 | 2 | `2088000000000002` | 测试支付宝用户B | https://mock-cdn.test/avatar/alipay_002.png |

#### 4.2.4 Mock Code 格式

```
mock_{provider}_{account_index}_{timestamp}

示例：
mock_wechat_1_1785060000
mock_douyin_2_1785060000
mock_alipay_1_1785060000
```

后端收到 Mock code 后：
1. 解析 `provider` 和 `account_index`
2. 从预设测试账号表查询对应的用户信息
3. 跳过真实 token 换取和用户信息接口调用
4. 直接进入"查找/创建用户 → 签发 JWT"流程

### 4.3 支付宝沙盒对接

#### 4.3.1 沙盒环境信息

| 配置项 | 沙盒值 |
|-------|--------|
| 沙盒入口 | https://open.alipay.com/develop/sandbox/app |
| 沙盒 AppID | 沙箱页面获取（以 2021 开头） |
| 网关地址 | `https://openapi-sandbox.dl.alipaydev.com/gateway.do` |
| 应用私钥 | 沙箱页面生成或上传 RSA2 密钥对 |
| 支付宝公钥 | 沙箱页面查看 |
| 沙箱版支付宝钱包 | 下载沙箱版支付宝 APP 进行授权测试 |

#### 4.3.2 沙盒模式配置

```env
# 支付宝沙盒开关
ALIPAY_SANDBOX=true

# 沙盒凭证（从沙箱页面获取）
ALIPAY_APP_ID=2021000122633371
ALIPAY_APP_PRIVATE_KEY=沙箱应用私钥
ALIPAY_PUBLIC_KEY=沙箱支付宝公钥

# 沙盒网关（自动切换，无需手动配置）
# 生产：https://openapi.alipay.com/gateway.do
# 沙箱：https://openapi-sandbox.dl.alipaydev.com/gateway.do
```

#### 4.3.3 沙盒模式行为

| 行为 | 说明 |
|------|------|
| 网关自动切换 | `ALIPAY_SANDBOX=true` 时，所有支付宝请求自动走沙箱网关 |
| 签名验证 | 使用沙箱 RSA2 密钥对进行真实签名验签 |
| 授权流程 | 使用沙箱版支付宝 APP 扫码授权 |
| 用户信息 | 调用 `alipay.user.info.share` 返回沙箱测试用户信息 |
| 其他平台不受影响 | 微信/抖音仍走 Mock 模式 |

### 4.4 运行模式切换矩阵

| 场景 | OAUTH_MOCK_MODE | ALIPAY_SANDBOX | 微信 | 抖音 | 支付宝 |
|------|----------------|----------------|------|------|--------|
| 纯开发调试 | true | false | Mock | Mock | Mock |
| 支付宝真实联调 | true | true | Mock | Mock | 沙箱真实接口 |
| 微信测试号联调 | true | false | 微信测试号 | Mock | Mock |
| 全部上线 | false | false | 真实接口 | 真实接口 | 真实接口 |

### 4.5 阶段切换策略

```
阶段一：开发阶段（当前）
    OAUTH_MOCK_MODE=true
    三平台均走 Mock，完成前后端全链路开发联调
    ↓
阶段二：部分联调阶段
    ALIPAY_SANDBOX=true，支付宝切换沙箱真实接口
    微信/抖音仍走 Mock
    ↓
阶段三：企业认证通过
    OAUTH_MOCK_MODE=false
    填入真实凭证，三平台全部切换真实接口
    ↓
阶段四：生产上线
    OAUTH_MOCK_MODE=false
    ENV=production
    配置生产域名回调地址
```

## 五、API 接口设计

### 5.1 统一接口规范

所有第三方登录共用一套接口，通过 `{provider}` 参数区分平台：

| 接口 | 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|------|
| 获取授权 URL | GET | `/auth/oauth/{provider}/authorize` | 无 | 返回第三方授权页跳转地址（Mock 模式返回本地 Mock 页地址） |
| 登录回调 | POST | `/auth/oauth/{provider}/callback` | 无 | 提交 code 完成登录/注册 |
| 绑定第三方 | POST | `/auth/oauth/{provider}/bind` | Bearer | 已登录用户绑定第三方账号 |
| 解绑第三方 | DELETE | `/auth/oauth/{provider}/unbind` | Bearer | 解除第三方账号绑定 |
| 查询绑定列表 | GET | `/auth/oauth/bindings` | Bearer | 查询当前用户已绑定的第三方账号 |
| **Mock 授权页** | GET | `/mock/oauth/{provider}` | 无 | Mock 模式下的模拟授权页面（v2 新增） |

`{provider}` 取值：`wechat` / `douyin` / `alipay`

### 5.2 响应格式

```json
// GET /auth/oauth/{provider}/authorize（真实模式）
{
  "authorize_url": "https://open.weixin.qq.com/connect/qrconnect?appid=..."
}

// GET /auth/oauth/{provider}/authorize（Mock 模式）
{
  "authorize_url": "http://localhost:5173/mock/oauth/wechat?state=xxx"
}

// POST /auth/oauth/{provider}/callback
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer"
}

// GET /auth/oauth/bindings
[
  {
    "provider": "wechat",
    "oauth_uid": "o6_bmjrPTlm6_2sgVt7hMZOPfL7M",
    "created_at": "2026-07-26T10:00:00"
  }
]
```

## 六、数据库设计

### 6.1 新增表：oauth_accounts

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK, 自增 | 主键 |
| user_id | Integer | FK → users.id, NOT NULL | 关联本站用户 |
| provider | String(20) | NOT NULL | 平台标识：wechat / douyin / alipay |
| oauth_uid | String(100) | NOT NULL | 第三方用户唯一 ID |
| access_token | String(500) | nullable | 第三方 access_token |
| refresh_token | String(500) | nullable | 第三方 refresh_token（支付宝） |
| expires_at | DateTime | nullable | 第三方 token 过期时间 |
| created_at | DateTime | 默认当前时间 | 绑定时间 |
| updated_at | DateTime | 自动更新 | 更新时间 |

**约束：**
- UNIQUE(provider, oauth_uid) — 同一第三方账号不可重复绑定
- INDEX(user_id, provider) — 按用户查询绑定列表

### 6.2 users 表

无需新增字段，第三方登录时自动创建用户，密码字段存随机字符串。

### 6.3 Mock 模式数据说明

Mock 模式创建的用户数据与真实模式完全一致，区别仅在于：
- `oauth_accounts.provider` 仍为 `wechat` / `douyin` / `alipay`
- `oauth_accounts.oauth_uid` 为 Mock 预设的测试 ID
- `users` 表中自动注册的用户名格式为 `{provider}_测试用户X`

切换到真实模式后，Mock 数据保留但不会影响真实登录（openid 不同）。

## 七、配置项需求

### 7.1 环境变量（.env）

```env
# ===========================================
# OAuth 运行模式（v2 新增）
# ===========================================
# Mock 模式开关：true=模拟OAuth流程，false=调用真实第三方接口
# 开发阶段推荐 true，生产环境必须 false
OAUTH_MOCK_MODE=true

# 支付宝沙箱开关：true=使用支付宝沙箱环境
# 仅在 OAUTH_MOCK_MODE=true 时对支付宝生效
# Mock 模式下支付宝优先走沙箱（如已配置沙箱凭证），否则走 Mock
ALIPAY_SANDBOX=false

# 前端回调地址
OAUTH_FRONTEND_URL=http://localhost:5173

# ─── 微信 ───
# AppID 格式：wx + 16位十六进制；AppSecret 为 32 位十六进制
# 申请地址：https://open.weixin.qq.com/
WECHAT_CLIENT_ID=<your_wechat_appid>
WECHAT_CLIENT_SECRET=<your_wechat_app_secret>

# ─── 抖音 ───
# ClientKey / ClientSecret 在抖音开放平台应用详情页获取
# 申请地址：https://open.douyin.com/
DOUYIN_CLIENT_ID=<your_douyin_client_key>
DOUYIN_CLIENT_SECRET=<your_douyin_client_secret>

# ─── 支付宝（生产） ───
# AppID 为 16 位数字；应用私钥/支付宝公钥为 RSA2 PEM 格式（多行 Base64）
# 申请地址：https://open.alipay.com/
ALIPAY_APP_ID=<your_alipay_app_id>
ALIPAY_APP_PRIVATE_KEY=<your_alipay_app_private_key>
ALIPAY_PUBLIC_KEY=<your_alipay_public_key>

# ─── 支付宝沙盒（v2 新增） ───
# 从 https://open.alipay.com/develop/sandbox/app 获取
# 凭证格式与生产环境一致，但仅用于沙箱环境调用
ALIPAY_SANDBOX_APP_ID=<your_sandbox_app_id>
ALIPAY_SANDBOX_APP_PRIVATE_KEY=<your_sandbox_app_private_key>
ALIPAY_SANDBOX_PUBLIC_KEY=<your_sandbox_public_key>
```

### 7.2 配置优先级

```
对于支付宝：
1. ALIPAY_SANDBOX=true 且已配置沙箱凭证 → 走沙箱真实接口
2. ALIPAY_SANDBOX=false 且 OAUTH_MOCK_MODE=true → 走 Mock
3. ALIPAY_SANDBOX=false 且 OAUTH_MOCK_MODE=false → 走生产真实接口

对于微信/抖音：
1. OAUTH_MOCK_MODE=true → 走 Mock
2. OAUTH_MOCK_MODE=false 且已配置凭证 → 走真实接口
3. OAUTH_MOCK_MODE=false 且未配置凭证 → 返回配置错误
```

## 九、安全需求

| 安全项 | 实现方式 |
|-------|---------|
| CSRF 防护 | 生成随机 state，回调时校验一致性（Mock 模式同样校验） |
| Code 一次性 | 第三方 code 使用后立即失效，不可重放（Mock code 含时间戳，5 分钟过期） |
| Token 安全 | 第三方 access_token 加密存储，不暴露给前端 |
| 绑定鉴权 | 绑定/解绑接口需 Bearer Token 认证 |
| 回调域校验 | 后端校验 redirect_uri 与配置一致 |
| 日志审计 | 记录所有 OAuth 登录/绑定/解绑操作（Mock 模式日志标记 `[MOCK]`） |
| **Mock 模式安全（v2 新增）** | 生产环境启动时强制校验 `OAUTH_MOCK_MODE=false`，否则拒绝启动 |
| **Mock Code 时效（v2 新增）** | Mock code 含时间戳，后端校验 5 分钟内有效 |

## 十、异常处理

| 场景 | HTTP 状态码 | 错误信息 |
|------|------------|---------|
| 不支持的 provider | 400 | 不支持的登录方式: {provider} |
| 平台未配置 | 500 | {provider} 登录未配置，请在 .env 中设置 |
| state 校验失败 | 400 | State 校验失败，可能存在 CSRF 攻击 |
| code 已过期或已使用 | 400 | 授权码无效或已过期 |
| 第三方账号已被绑定 | 400 | 该第三方账号已被其他用户绑定 |
| 重复绑定同一平台 | 400 | 您已绑定了 {provider} 账号，请先解绑 |
| 未绑定却尝试解绑 | 404 | 未绑定 {provider} 账号 |
| 第三方接口异常 | 500 | 第三方服务暂时不可用，请稍后重试 |
| **生产环境开启 Mock（v2 新增）** | 500 | 生产环境禁止开启 Mock 模式，请设置 OAUTH_MOCK_MODE=false |
| **Mock code 过期（v2 新增）** | 400 | Mock 授权码已过期，请重新授权 |
| **Mock code 格式错误（v2 新增）** | 400 | Mock 授权码格式无效 |
