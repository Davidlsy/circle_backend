# 游客访问（免登录浏览）前端需求

## 1. 功能概述

系统支持游客模式：用户未登录即可浏览帖子、评论、图片、视频等内容，但不能进行点赞、评论、收藏等互动操作。前端需针对游客与登录用户做差异化交互处理。

## 2. 游客可见/可操作范围

### 2.1 游客可访问（无需 token）

| 页面/功能 | 接口 | 说明 |
|----------|------|------|
| 帖子列表页 | `GET /posts/` | 仅返回 `status=approved` 的帖子 |
| 帖子详情页 | `GET /posts/{post_id}` | 仅可查看 `approved` 帖子 |
| 评论列表 | `GET /posts/{post_id}/comments` | 仅返回 `approved` 评论 |
| 帖子图片 | `GET /posts/{post_id}/images` | 公开 |
| 帖子视频 | `GET /posts/{post_id}/videos` | 公开 |
| 热门推荐 | `GET /posts/recommended` | 公开 |
| 加精帖子 | `GET /posts/featured` | 公开 |
| 静态资源 | `/uploads/{filename}` | 图片/视频/封面 |

### 2.2 游客被禁止操作（需 token，后端返回 401）

| 操作 | 接口 |
|------|------|
| 点赞帖子 | `POST /posts/{post_id}/like` |
| 收藏帖子 | `POST /posts/{post_id}/collect` |
| 评论帖子 | `POST /posts/{post_id}/comments` |
| 评论点赞 | `POST /posts/comments/{comment_id}/like` |
| 发帖/编辑/删除帖子 | `POST/PUT/DELETE /posts/...` |
| 上传图片/视频 | `POST /posts/{post_id}/images\|videos` |
| 关注/粉丝、消息、签到等用户态功能 | 各自接口 |

## 3. 前端交互需求

### 3.1 Token 管理

- 登录成功后，将 `access_token` 存储于本地（localStorage / Pinia / Vuex）。
- 所有需鉴权的请求在 Header 中携带：`Authorization: Bearer <token>`。
- 游客浏览时不携带该 Header，后端按"未登录"处理，返回数据中 `is_liked` / `is_collected` 字段为 `false`。

### 3.2 路由守卫

- **公开路由**（游客可访问）：首页、帖子列表、帖子详情、明星主页、热门推荐、加精列表。
- **受保护路由**（必须登录）：发帖页、个人中心、消息、我的收藏、我的粉丝/关注、签到等。
- 访问受保护路由时未登录 → 重定向到登录页，并通过 query 携带 `redirect` 参数，登录后跳回原页面。

### 3.3 互动按钮的游客处理

在帖子详情/列表页，点赞、收藏、评论按钮的统一行为：

1. **未登录点击互动按钮**：
   - 弹出提示（Toast / Modal）：`请先登录后再操作`
   - 点击"去登录"跳转至登录页，携带 `redirect` 回跳当前页
   - **不调用后端接口**，避免无谓的 401 请求
2. **已登录点击互动按钮**：
   - 正常调用接口，乐观更新 UI
   - 接口失败时回滚 UI 状态并提示错误

### 3.4 接口 401 全局处理

虽然前端做了拦截，但 token 过期/被踢下线仍可能发生：

- axios / fetch 拦截器捕获 `401` 响应：
  - 清除本地 token
  - 弹出提示 `登录已过期，请重新登录`
  - 跳转登录页（保留 `redirect`）
  - 不影响当前正在浏览的公开内容

### 3.5 数据字段差异化展示

帖子详情/列表接口对游客返回的字段：

| 字段 | 游客值 | 登录用户值 |
|------|--------|-----------|
| `is_liked` | `false` | 真实状态 |
| `is_collected` | `false` | 真实状态 |
| `like_count` / `comment_count` / `collection_count` | 真实数字 | 真实数字 |

前端需保证：游客看到的计数是真实的，但点赞/收藏按钮呈"未激活"态。

### 3.6 帖子状态提示

- 游客仅能看到 `status=approved` 的帖子。
- 当游客通过 URL 直接访问 pending/rejected 帖子时，后端返回 404，前端展示"帖子不存在或已被删除"。

## 4. UI 状态规范

| 元素 | 游客态 | 登录态 |
|------|--------|--------|
| 顶部导航 | 显示「登录 / 注册」按钮 | 显示用户头像 + 下拉菜单 |
| 点赞按钮 | 灰色未激活，点击触发登录引导 | 根据真实状态高亮 |
| 收藏按钮 | 灰色未激活，点击触发登录引导 | 根据真实状态高亮 |
| 评论输入框 | 显示「登录后评论」占位，点击聚焦时弹登录框 | 正常输入框 |
| 发帖入口 | 隐藏或显示「登录后发帖」提示 | 正常显示 |
| 评论点赞 | 同帖子点赞 | 同帖子点赞 |

## 5. 推荐交互流程示例

**游客点击帖子点赞按钮**：

```
点击点赞
  ├─ 检测无 token
  │    └─ 弹出 Modal: "请先登录"
  │         ├─ [去登录] → /login?redirect=/posts/123
  │         └─ [取消] → 关闭
  └─ (有 token 时)
       └─ POST /posts/123/like
            ├─ 200 → 更新 UI
            └─ 401 → 清 token + 跳登录
```

## 6. 注意事项

1. 游客模式不应被前端"伪造"为登录用户，禁止伪造 token 或本地造 `is_liked=true`。
2. 帖子浏览量 `view_count` 由后端在 `GET /posts/{post_id}` 中自增，游客访问也会计入，前端无需额外处理。
3. 静态资源（图片/视频/缩略图）走 `/uploads/{filename}`，无鉴权，可直接 `<img src>` / `<video src>` 引用。
4. 明星主页、标签页等如果未来需要登录，应同步纳入路由守卫；当前默认公开。
